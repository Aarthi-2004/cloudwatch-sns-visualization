      Complete architecture

      EC2 instance → CloudWatch metrics → CloudWatch alarm → SNS topic → Email subscription → Aarthi

      This design detects and notifies. It does not reduce CPU or repair the instance; automatic remediation or scaling needs extra configuration (for example Auto Scaling or an alarm action that runs automation).

      Troubleshooting checklist for a Cloud Support Engineer

      • Alarm stuck in INSUFFICIENT_DATA? Check the instance is running, the right metric, dimension (InstanceId), namespace (AWS/EC2), period and missing-data treatment.
      • No email? Confirm the alarm has an action for the ALARM state, the topic ARN is correct, and the subscription is Confirmed (not PendingConfirmation). Check spam folders.
      • Metrics look delayed? Basic monitoring is typically 5-minute granularity; detailed monitoring is 1 minute and may cost extra.
      • Review the alarm's history tab and SNS delivery logging to see what actually happened.
      • High CPU is a symptom, not a verdict: investigate the workload before changing instance size.
